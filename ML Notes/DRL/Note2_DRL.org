* Rewards

** Reward Signals:
- The reward function R maps a transition tuples,a,s' to a scalar
- It gives a numerical signal of goodness to transitions
  - When the signal is positive it is looked at as a reward
    - Rewards are not always good. They can be negative and we can see this as a punishment/penalty
*Formulas:*
1. Reward function for \( r(s, a) \):
\[
R_t = r(s_t, a_t) \quad \text{where} \quad E[R_t | s_{t->1} = s, a_{t->1} = a] = r(s, a)
\]
2. Reward function for \( r(s, a, s') \):
\[
R_t = r(s_t, a_t, s_{t+1}) \quad \text{where} \quad E[R_t | s_{t->1} = s, a_{t->1} = a, s_t = s'] = r(s, a, s')
r(s, a) = R(s, a) \\
\]

** Time Step:
- A time step/cycle is a global clock syncing all parties
- Having a clock is extremely useful in RL/DRL
 - It allows the use of Task

* Task Types:
*** Episodic Task
- A task in which there's a finite amount of time steps/cycles
- Usually because the clock stops or beachhead the agent hits a terminal state
  *EX:* Think about a task that has a clear goal like a chess game once you do a certain move its game over
*** Continuing tasks
- Like the name suggest these task go on forever there are no terminal state
- The agent must be stopped manually
  *Ex:* Think about a robot cleaning a room. The task never ends until someone shuts it off


** Planning Horizon:
- A planning horizon is just essentially just how far ahead an agent thinks about it's task
*Types:*
*** Finite Horizon:
- The agent has and knows there is a set number of moves it can take to finish a task
 - The task has a strict limit on how long it will take
*** Greedy Horizon:
- A type of _Finite Horizon_
- The task completes immdieately after one action (*Almost like choosing between two options Right or Wrong*)
    *EX:* The bandit walk is an example of the greedy horizon
*** Infinite Horizon:
- The agent dosen't know ahead of time when the task will end.
 *Even if the task does have a finishing point*
* Discounts
- The issue with DRL/RL is the possibility of infinite sequences of time steps in infinite horizon tasks
  - so we need a way to discount the value of rewards overtime( *We need a way to tel the agent that +1 is good*)
- So the further into the future we recieve the rewards, the less valuable it is in the present.
  - We call this the _Discount Factor/Gamma_
    - The discount factor allows us to stabilize learning for most agents
